# Capstone reference implementation — student-support early warning

> **Synthetic data, educational system.** Every record is generated by
> [`generate_data.py`](generate_data.py); there is no real student data here.
> The model is a **triage aid for human counsellors**, never an automated
> decision about a person.

This is the working reference for **Module 17** — a complete, local,
free MLOps system: data → validation → training → gate → tests → API →
container → CI → monitoring → release/rollback → governance. It reuses the
patterns from Modules 01–16 instead of introducing new tools.

**Everything below was executed on the authoring machine (Windows 11,
Python 3.14) and the outputs shown are real.** Two things were *not* executed
here and are labelled honestly at the bottom.

## 2. The scenario

A support team wants an **early alert** for students who may need help:
predict `at_risk` from engagement features (attendance, prior score, LMS
logins, missed assessments, assignment rate, device access). Success is
pre-specified in [`config.yaml`](config.yaml): `roc_auc_floor: 0.75`, plus a
selection-rate fairness audit across `device_access` groups with a stated
(max) target of 0.10.

**Provenance:** 100% synthetic, seeded (`seed: 20261026`), openly usable —
no licence encumbrance, no personal data.

## 4. Release governance (real run)

```powershell
python release.py register --note "capstone v1"
python release.py promote r001                              # refused (see below)
python release.py promote r001 --ack "gap documented in risk register"
python release.py history
```

Real output:

```text
registered r001  roc_auc=0.7662  gate=True  fairness_ok=False
  note: fairness gap 0.1318 was OVER target at registration - promotion will need --ack
refused: r001 has an OVER-TARGET fairness gap (0.1318) - promote with --ack "reason recorded for the risk register"
r001 is now serving (was None)
  risk acceptance recorded: gap documented in risk register
```

The over-target gap is **real in this synthetic data** and is the point of the
exercise: the system documents a known limitation rather than hiding it
(Module 15's governance lesson).

## 5. Monitoring (real run)

```powershell
python monitor.py snapshot
python monitor.py log                       # baseline window, no labels yet
python monitor.py log --shifted --labels    # replayed shift WITH labels
python monitor.py drift
python monitor.py performance
python monitor.py decision
```

Real output — note the teaching outcome: **strong drift, yet accuracy did not fall**:

```text
  attendance_rate      psi=0.8635  strong
  prior_score          psi=0.01    stable

```

Drift ≠ accuracy decline (Module 14) — labels decide.
