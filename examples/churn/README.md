# Shared example project — Lahore Retail Co. churn

This is the **single worked example** that the course builds across Modules 01–14
(and beyond). One scenario, one dataset, one repository shape — so you are never
re-learning a new fictional world every week.

> **Ethics note:** every dataset here is **synthetic** — generated by
> `generate_data.py` from a fixed random seed. No real person's data is used or
> imitated. Licence: CC0 (public domain) — use it for anything.

## The story

**Lahore Retail Co.** is a mid-size retailer with a subscription plan. Data
science has built a model that predicts which customers will churn (cancel) in
the next month. The model works in the notebook. Nobody can say exactly which
code produced it, whether the data it was trained on is the same data the
business reports, or what happens when it starts being wrong. The course fixes
that, one module at a time.

## How this folder evolves

| Module | What appears here |
|---|---|
| 01 | `01-autopsy/` — the incident bundle you investigate |
| 02 | `pyproject.toml`, `.gitignore` — a reproducible environment |
| 03 | `legacy/analysis.ipynb` — the messy notebook you restructure into `src/` |
| 04 | `generate_data.py`, `src/validate.py` — data checks and versioning |
| 05 | `config.yaml`, `src/features.py`, `src/train.py` — reproducible training |
| 06 | `experiments/train_mlflow.py` — experiment tracking with MLflow |
| 07 | `tests/` — an automated test suite you can run |
| 08 | `pipe/` — a declared DAG: incremental runs, gates, failure resume |
| 09 | `registry/` — model versions, promotion rules, rollback (local files) |
| 10 | `service/` + `tests/test_service.py` — the FastAPI prediction API |
| 11 | `Dockerfile`, `.dockerignore`, `requirements-docker.txt` — the image |
| 12 | `ml_check.py` + `.github/workflows/ci.yml` (repo root) — CI gates |
| 13 | `orchestrate/` — scheduled runs, retries, history, alerting |
| 14 | `monitoring/` — prediction log, drift, performance, decisions |

Nothing here is required to *read* the course — it exists so the labs can point at
real, runnable code instead of invented screenshots.

## Regenerating the data

```powershell
# 🪟 Windows / PowerShell, from this folder
python generate_data.py
```

```bash
# 🐧 Linux / macOS
python3 generate_data.py
```

The generator is deterministic: the same seed always produces byte-identical
CSV files, which is exactly the property Modules 04 and 05 are about.

## Files you should not treat as course material

`01-autopsy/` contains **deliberately bad** logs and metrics — that is the point
of Lab 01. Everything else is a working example, not a finished product.
