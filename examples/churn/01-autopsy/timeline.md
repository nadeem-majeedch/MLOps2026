# Incident timeline — "the score silently rotted"

> **This is fiction, written for teaching.** Every number in this folder was
> generated by `make_fixture.py`. It is not a real company, a real incident, or a
> real measurement — but the *shape* of this failure is one every ML team meets.
>
> Dates below match `metrics_snapshot.csv` exactly (60 days, 2026-07-01 → 2026-08-29).

**Affected system:** a churn-risk scoring model used by a subscription business.
**Unnoticed decay:** from 11 Aug until detection. **Human cost:** ~3 weeks of
analyst time and one rolled-back release.

| Date | What happened | What the team saw |
|---|---|---|
| 01 Jul – 10 Aug | Model `v2` in production, scoring ~420 customers/day, AUC ≈ 0.78 | Nothing. Dashboards green. |
| ~21 Jul | An upstream engineer changes how `contract_type` values are stored | A schema change nobody flagged to the ML team |
| 11 Aug | A data scientist promotes model `v3` straight from a notebook. **No registry entry, no review, no rollback point** | A chat message: "new model is live 🎉" |
| 14 Aug | Measured AUC slips below 0.75 | One analyst notices and assumes it is label delay |
| 15 Aug | Missing-value rate in `monthly_charges` jumps from ~0.4% to ~7% | **Not monitored at all** |
| 18 Aug | Drift score crosses 0.15 (and keeps climbing past 0.35) | **No threshold was ever set**, so nothing alerts |
| 20 Aug | p95 latency rises ~90 ms (a slower feature join in `v3`) | Visible only if someone opens the right dashboard |
| 24 Aug | A customer-success manager reports "scores look wrong for month-to-month plans" | The first human complaint |
| 25–26 Aug | Investigation: `v3` was trained on a March snapshot with a feature pipeline that no longer matches production | Root cause found |
| 26 Aug | `v3` rolled back to `v2`; scores immediately return to normal | Fix measured, not assumed |
| 27 Aug+ | Retraining scheduled "sometime next sprint" | The actual work begins |
