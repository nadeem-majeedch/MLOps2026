# Known limitations

Everything below is a **known, accepted, or environmental limitation** of this
course repository as of the final audit (2026-10-27). Nothing here is hidden
elsewhere: if a check could not be run, it is listed. Full evidence:
[final-quality-report.md](final-quality-report.md).

---

## 1. Environment gaps on the audit machine

| Limitation | Effect | What closes it |
|---|---|---|
| **Docker CLI not installed** | `docker build` for Lab 12, Lab 16, `examples/churn/Dockerfile` and `examples/capstone-support/Dockerfile` was **not executed**; Dockerfiles were reviewed statically | Run the container steps on any machine with Docker Desktop/Engine (Lab 12 §commands) |
| **kubectl not installed** | Kubernetes steps (Module 16, Lab 16) could not run | Install `kubectl` + kind/minikube, or use Lab 16's documented Path B (local simulation) |
| **actionlint not installed** | GitHub workflows are YAML-parse-checked only, not schema-validated | `actionlint .github/workflows/*.yml` on any machine, or rely on the first Actions run |
| **No `.git` directory in this workspace copy** | `git status`, tracked-file scans, and history review were impossible here; all results are filesystem-based | Re-run verification from a real clone before committing |

## 2. Content limitations (by design)

- **Some tests fail on purpose.** `examples/labs/lab-13/test_compat.py` (uses
  the removed `np.float`) and `examples/labs/solutions/lab-15/test_release_gate.py`
  ("AS SHIPPED these tests FAIL") are the exercises themselves. Their expected
  as-shipped state is documented in their docstrings and solution READMEs, and
  no CI workflow runs them.
- **Some tests skip on purpose.** `lab-10` and `security-lab` tests skip until
  the student creates `app.py` / `fixed/` — the skip reason says so.
- **137 pages are not in the MkDocs nav** (module sub-pages plus the
  `PREREQUISITES.md` pointer stub). They are reachable from each module's
  in-page links; MkDocs reports this at INFO level. Restructuring nav is an
  owner decision, not an audit repair.
- **No content images.** The course uses tables, ASCII diagrams, and code for
  illustration; the only image shipped is the theme favicon. Template guidance
  for adding images lives in [website-development.md](website-development.md) §5.
- **MkDocs anchor checking is soft.** MkDocs 1.6 reports missing `#anchors`
  under `--strict` as INFO, not WARNING. Enabling `anchors: warn` is an
  opt-in owner decision (documented in [build-and-validation.md](build-and-validation.md)).

## 3. Licensing and data

- **No `LICENSE` file yet** — the root README says so honestly ("ask the
  instructor before redistributing"). Publication without adding one leaves
  reuse terms undefined. Owner decision required.
- All datasets are **synthetic and generated by repository code**
  (`datasets/README.md`); no third-party data is redistributed, so no data
  licence obligations exist — but the *code/content* licence is still open.

## 4. Toolchain lifecycle

- **Material for MkDocs reaches end-of-life on 2027-05-05** (printed by our own
  build). Critical fixes continue to that date; migration guidance is in
  [maintenance.md](maintenance.md).
- The churn test suite emits one **upstream** deprecation warning
  (Starlette `TestClient`/`httpx`) — harmless, not course code.
- A local `examples/churn/.venv/` exists on the audit machine. It is
  git-ignored and never tracked.

## 5. Scope boundaries of the audit

- **Executed:** integrity checks, strict site build, 95 student-facing tests,
  deterministic data generation, capstone training, lint, `pip check`,
  pin-vs-installed comparison, YAML parsing, secret-pattern scan, artifact-size
  scan, README policy scan, instructor-information scan.
- **Not executed:** Docker/Kubernetes runs, `actionlint`, MLflow-tracking and
  DVC end-to-end lab runs (packages verified importable: mlflow 3.17.2,
  dvc 3.67.1), GitHub Pages deployment, anything requiring git or a push.
