## Set up your portfolio (day 4)

Every module asks you to produce **evidence**: logs, reports, diagrams, test
output. Keep it all in one Git repository you own:

```
portfolio/
├── modules/          evidence per module
├── mini-projects/    MP1–MP5
├── capstone/         final system + evidence bundle
└── REFLECTION.md     what broke, what you would do differently
```

You will not be graded by anyone — but a portfolio you can show another person is
the difference between *having studied* and *being able to prove it*. Details:
[course project map](../syllabus/course-project-map.md).

## How a module works

Each module has the same five parts, so you always know what is coming:

1. **Lessons** — concepts and vocabulary, before any tool appears.
2. **Guided lab** — a realistic scenario with numbered steps, expected output,
   troubleshooting, and cleanup.
3. **Independent challenge** — an open-ended task with no step-by-step directions.
4. **Assessment** — a knowledge check plus a practical, with self-gradable rubrics.
5. **Evidence** — what you file in your portfolio to prove the outcomes.

Work in this rhythm: read → lab → challenge → self-assess → file evidence →
tick the [progress checklist](progress-checklist.md).

## The rules that protect your time

- **Work in module order.** Each gate assumes the previous ones.
- **Never skip a ✅ verification step.** An unverified step is how you end up
  stuck three modules later with an invisible broken setup.
- **Skip optional content first**, never the guided lab.
- **Stopped by an error?** Go to [Troubleshooting](../troubleshooting/index.md)
  before you improvise — the common failures are already written up.
- **Re-entering after a break?** Re-run the verification step of the last lab you
  finished. It tells you what still works.
