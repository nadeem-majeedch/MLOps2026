# Datasets used by this course

Everything the course runs on is **synthetic and generated by code in this
repository**. There is no personal data, no scraped data, and no third-party
dataset to download — a deliberate design choice so the course can be run
anywhere, offline, forever, without asking anyone for credentials or a
licence review.

> **Rule of the house:** *small committed CSVs, regenerable everything else.*
> Datasets below are a few hundred kilobytes and are committed so a fresh
> clone works immediately. Model binaries and other generated outputs are
> **not** committed — they are reproduced with the commands listed here
> (see [What is committed vs regenerated](#what-is-committed-vs-regenerated)).

---

## 1. Selection criteria (why synthetic)

| Criterion | How this course meets it |
|---|---|
| **Licence** | Generated by our own scripts → no redistribution restriction. Nothing is copied from a third party. |
| **Privacy** | No real students, customers, or patients. IDs are synthetic (`CUST-0001`, `S100000`) and cannot identify anyone. |
| **Reproducibility** | Every generator uses a fixed seed, fixed row order and fixed float formatting → byte-identical output on every machine. |
| **Size** | ~0.5 MB of CSVs in total; fits comfortably in a Git repository. |
| **Pedagogy** | Each dataset is *designed* to contain the exact defect a lab needs (dirty values, duplicates, schema drift, distribution shift). |
| **Cost** | Free, CPU-only, no cloud account, no API key. |

**Never** commit real personal data, production extracts, or licensed
corporate data to this repository. If you need a real dataset for your
capstone, check its licence first (§4) and keep it out of Git if it is large.

### 2.1 Laboratory datasets — `examples/labs/data/`

Generated by [`examples/labs/make_data.py`](https://github.com/nadeem-majeedch/MLOps/tree/main/examples/labs/make_data.py)

```powershell
# 🪟 Windows — PowerShell
cd examples\labs
python make_data.py            # writes ./data/*.csv
python make_data.py --check    # regenerate + verify byte-identical output
```
```bash
# 🐧 Linux/macOS
cd examples/labs && python make_data.py && python make_data.py --check
```

| File | Rows | Used by | What is special about it |
|---|---|---|---|
| `customers_clean.csv` | 600 | labs 04, 05, 06, 08, 09, 10, 12, 14, 16, 18 | healthy schema, honest signal + noise |
| `customers_dirty.csv` | 600 | lab 03 | missing values, out-of-range values, duplicate rows, one column removed / one added (schema drift) |
| `customers_shifted.csv` | 600 | lab 17 | `monthly_charges`, `support_calls` deliberately shifted (distribution drift) |

**Schema (`customers_clean.csv`)**

| Column | Type | Range / values | Meaning |
|---|---|---|---|
| `customer_id` | string | `CUST-0001` … `CUST-0600` | synthetic key, not a person |
| `tenure_months` | int | 1–71 | months as a customer |
| `monthly_charges` | float | 15.0–160.0 | monthly fee (2 dp) |
| `support_calls` | int | 0–11 | support calls last month |
| `contract_type` | category | `monthly` \| `one_year` \| `two_year` | contract |
| `churned` | int | 0 \| 1 | target |

Sample record:

```csv
CUST-0001,44,24.3,2,monthly,0
```

### 2.3 Capstone dataset — `examples/capstone-support/data/support.csv`

Generated by [`examples/capstone-support/generate_data.py`](https://github.com/nadeem-majeedch/MLOps/tree/main/examples/capstone-support/generate_data.py)
(seed `20261026`, 3 000 rows) — synthetic educational data for the
student-support early-alert scenario. **Fictional students only**: no real
roster, no names, no contact details, no identifiers of any real person.

**Schema (`support.csv`)**

| Column | Type | Range | Meaning |
|---|---|---|---|
| `student_ref` | string | `S100000`… | synthetic reference, not a person |
| `attendance_rate` | float | 0.3–1.0 | attendance fraction |
| `prior_score` | float | 0–100 | prior academic score |
| `lms_logins` | int | ≥0 | LMS logins in the window |
| `missed_assessments` | int | ≥0 | missed assessments |
| `assignment_rate` | float | 0–1 | assignments submitted on time |
| `device_access` | int | 0 \| 1 | reliable device at home |
| `term_end_flag` | int | 0 \| 1 | **leakage trap** — future information the pipeline must refuse |
| `at_risk` | int | 0 \| 1 | target |

Sample record:

```csv
S100000,0.824,69.5,14,1,0.775,1,0,0
```

The `term_end_flag` column is present **on purpose**: Module 07/10/17
teach leakage prevention, and `python -m src.validate` must reject any
pipeline that would let it become a feature.

## 3. Reproducibility contract

1. **Fixed seed** — every generator calls `np.random.default_rng(SEED)`
   with a seed constant written at the top of the file.
2. **Fixed row order** — rows are produced in one pass; no shuffling at
   generation time.
3. **Fixed formatting** — floats rounded before writing, so CSV text is
   stable across platforms.
4. **Proof** — `python make_data.py --check` regenerates and compares
   hashes; on the authoring machine it reports byte-identical files.
   Re-run it yourself; a hash you did not compute is not evidence.

If your regenerated file differs: check that you ran the script from its
own folder, that no local edits touched `data/`, and that your NumPy
version is the pinned one (`numpy==2.5.3` in the example requirements).

## 5. What is committed vs regenerated

**Committed (small, needed for a fresh clone to work):**

- `examples/labs/data/*.csv` (64 KB total)
- `examples/churn/data/raw/*.csv`, `data/corrupt/*.csv` (~308 KB)
- `examples/capstone-support/data/support.csv` (105 KB)
- `examples/capstone-support/monitoring_out/` — verified monitoring
  outputs that lab 17 analyses (kept deliberately; regenerating them is
  possible but the lab analyses the recorded window)
- configuration, tests, and documentation

**Not committed (regenerate with one command):**

| Output | Regenerate with |
|---|---|
| `*.joblib` model binaries | `python train.py` / `python pipeline.py` in the relevant folder |
| `artifacts/`, `pipe_out/`, `registry_store/`, `releases/` | the pipeline or release command documented in each README |
| `runs.jsonl`, `*.log`, `site/` | build/run artefacts — ignored via `.gitignore` |

**Size discipline:** keep any single committed file under ~1 MB and the
whole repository's data under a few MB. If a dataset would exceed that,
commit the generator or downloader plus a checksum — never the bytes.
